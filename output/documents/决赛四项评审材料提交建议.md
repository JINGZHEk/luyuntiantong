# 路云天瞳决赛评审材料提交建议

## 一、必须提交的四项评审材料

1. 作品设计文档：按 A/A-ST/A-ICV/B-EP1 对应模板制作 Word，提交时转为 PDF/A。
2. 源代码：ZIP 格式，小于 1GB，只包含团队拥有知识产权或获准使用的内容。
3. 作品介绍视频：MP4、H.264、5 分钟以内、小于 500MB。
4. 汇报答辩视频：MP4、H.264、8 分钟以内、小于 800MB，相当于 PPT 预答辩。

在线演示 URL 为可选加分材料，建议填写：`https://luyuntiantong-1.onrender.com`。

## 二、设计文档建议

- 全文必须匿名，不出现学校、团队名称、指导教师姓名、队员姓名、学号、电话、邮箱、Logo 或可识别照片。
- 赛项建议为 A-ICV，但必须以报名系统的原始赛项为准。
- 明确区分：已实现软件、在线模拟能力、硬件接口设计、线下实机结果、未来计划。
- 不提交没有原始实验记录支撑的召回率、MOTA、FDE、42ms、降本 80% 等数字。
- 如果没有已发表论文、授权专利或已登记软著，成果排名填写“--”，不要把计划申报写成已有成果。
- PDF 导出选择 PDF/A，嵌入字体，检查目录、图片清晰度、页码和匿名信息。

## 三、源代码 ZIP 建议

- 建议文件名仅使用 2-6 个英文字母或数字，例如 `LYTT26.zip`。
- 保留：`src/`、`frontend/src/`、`configs/`、`scripts/`、`tests/`、`Dockerfile`、依赖清单、README、许可证说明。
- 删除：`.git/`、`node_modules/`、`frontend/dist/`、`__pycache__/`、日志、数据库、模型大文件、缓存、个人路径、临时测试文件。
- 增加 `THIRD_PARTY_LICENSES.md`，列出 PyTorch、FastAPI、React、Three.js、YOLO/Ultralytics、DeepSORT 等第三方依赖及许可证。
- 模型权重若来源不明或不允许再分发，不放入 ZIP；在 README 中说明下载或训练方式。
- 上传前在一台干净环境中解压，按 README 完成一次安装、构建和启动。

## 四、作品介绍视频建议（5 分钟）

- 0:00-0:30：遮挡风险场景与作品一句话定位。
- 0:30-1:15：路侧感知、云端预测、车端决策、Web 展示总体架构。
- 1:15-3:30：在线大屏实际操作，演示场景切换、轨迹、风险、事件和回放。
- 3:30-4:20：数据清洗、STGNN 流程、预测日志和健康监控。
- 4:20-5:00：创新点、应用价值和线上/硬件展示边界。
- 全程使用 1920×1080、H.264、稳定码率，字幕字号不小于 28px；不要展示学校、姓名、账号、浏览器收藏栏和桌面隐私信息。

## 五、汇报答辩视频建议（8 分钟）

- 结构建议：问题 1 分钟、方案 1.5 分钟、实现 2 分钟、演示与结果 2 分钟、创新与团队贡献 1 分钟、边界与总结 0.5 分钟。
- 重点回答：为什么单车感知不够、为什么用时空轨迹、模型不可用时如何降级、指标如何复现、线上展示与硬件实物的关系。
- 不把在线常速度降级轨迹称为 STGNN 实测结果；若展示模型指标，应同步给出数据集、样本量、测试脚本和日志截图。

## 六、提交前最终检查

- 四个文件均可独立打开，视频可从头播放到结尾。
- 文件名只使用 2-6 个英文字母或数字，避免中文、空格、括号和超长名称。
- 设计文档 PDF/A 无匿名泄漏，源代码 ZIP 无密钥、密码、个人数据和不明版权素材。
- Render 在线链接提前唤醒，并保留 `onrender.com` 地址，不只依赖自定义域名。
- 截止前上传后重新下载一遍，核对文件类型、大小、时长和内容版本。
