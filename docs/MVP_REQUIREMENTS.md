# MVP 需求文档

> 项目：分布式多智能体车路协同遮挡感知平台
> 版本：v0.1 MVP
> 日期：2026-04-14

---

## 1. 项目背景

自动驾驶在遮挡条件下的"鬼探头"问题是亟待解决的长尾危险工况。单车感知受物理视距限制，识别滞后、决策窗口不足。本项目通过车路协同方案，利用路侧感知扩展车端视野，实现遮挡行人的提前预警与主动制动。

## 2. MVP 目标

**一句话目标**：在"鬼探头"场景下，路侧感知提前识别遮挡行人，通过V2X通信传递给车端完成主动制动，全过程在云端孪生可视化。

### 2.1 核心用户故事

| ID | 用户故事 | 优先级 |
|----|---------|--------|
| US-01 | 作为路侧感知系统，我能检测遮挡区域中的行人并预测其短时轨迹 | P0 |
| US-02 | 作为车端决策系统，我能接收路侧共享特征并融合自车状态做出制动决策 | P0 |
| US-03 | 作为云端孪生系统，我能实时3D展示场景态势并支持历史回放 | P1 |
| US-04 | 作为系统运维人员，我能在通信中断时确保车端安全降级 | P0 |
| US-05 | 作为研究人员，我能查看检测指标和对比实验结果 | P1 |

### 2.2 MVP 范围界定

**包含 (In Scope)**：
- 路侧行人检测 + 遮挡状态估计 + 短时轨迹预测（3s）
- 路侧到车端的特征共享通信链路
- 车端协同风险评估 + 分级制动决策
- 云端3D场景可视化 + 数据持久化 + 事件回放
- 通信中断平滑退化机制
- 基于 DAIR-V2X 数据集的离线评估

**不包含 (Out of Scope)**：
- 多路口大规模部署
- V2V（车与车通信）
- 端到端学习型决策
- 恶劣天气/夜间场景
- 安全认证/加密通信
- 移动端 App

## 3. 功能需求

### 3.1 路侧感知智能体 (Roadside Perception Agent)

| 需求ID | 功能描述 | 输入 | 输出 | 验收标准 |
|--------|---------|------|------|---------|
| F-RP-01 | 行人/车辆检测 | 路侧相机视频帧 | 检测框 (bbox, class, confidence) | mAP ≥ 0.5 (DAIR-V2X) |
| F-RP-02 | 时空图构建 | 连续多帧检测结果 | 时空图 (节点=目标, 边=关联) | 图结构正确，节点特征维度一致 |
| F-RP-03 | 遮挡状态估计 | 检测框 + 历史轨迹 | 遮挡等级 (无/轻度/中度/重度) | 遮挡分类准确率 ≥ 70% |
| F-RP-04 | 轨迹预测 | ST-GNN编码特征 | 未来3s轨迹 [(x,y)] | ADE < 1.0m, FDE < 2.0m |
| F-RP-05 | 特征压缩与发布 | 感知结果 | MQTT消息 | 单帧消息 < 10KB |

### 3.2 车端决策智能体 (Vehicle Decision Agent)

| 需求ID | 功能描述 | 输入 | 输出 | 验收标准 |
|--------|---------|------|------|---------|
| F-VD-01 | 特征接收与解码 | MQTT消息 | 路侧感知特征 | 解码延迟 < 10ms |
| F-VD-02 | 协同特征融合 | 路侧特征 + 自车感知 | 融合特征向量 | 融合后风险评估优于纯自车 |
| F-VD-03 | TTC计算 | 目标轨迹 + 自车状态 | TTC值 (秒) | 计算误差 < 0.5s |
| F-VD-04 | 碰撞风险评估 | TTC + 融合特征 | 风险等级 (安全/警告/危险/紧急) | 误报率 < 20% |
| F-VD-05 | 分级制动决策 | 风险等级 | 制动指令 (减速度) | 紧急场景制动响应 < 200ms |
| F-VD-06 | 平滑退化 | 通信状态 | 降级模式标志 | 断连后 500ms 内切换 |

### 3.3 云端孪生智能体 (Cloud Twin Agent)

| 需求ID | 功能描述 | 输入 | 输出 | 验收标准 |
|--------|---------|------|------|---------|
| F-CT-01 | 3D场景渲染 | 场景配置 | Three.js 渲染画面 | 30fps 稳定渲染 |
| F-CT-02 | 实时数据驱动 | WebSocket数据流 | 动态目标运动 | 延迟 < 500ms |
| F-CT-03 | 数据持久化 | MQTT数据流 | 时序数据库记录 | 数据完整性 > 99% |
| F-CT-04 | 历史回放 | 时间范围查询 | 回放动画 | 支持倍速播放 |
| F-CT-05 | 高危事件标注 | 风险等级触发 | 事件标记 + 检索 | 可按时间/类型检索 |

## 4. 非功能需求

| 需求ID | 类别 | 描述 | 指标 |
|--------|------|------|------|
| NF-01 | 延迟 | 路侧感知到车端决策的端到端延迟 | < 100ms (局域网) |
| NF-02 | 吞吐 | 路侧感知帧率 | ≥ 10 FPS |
| NF-03 | 可靠性 | 通信断连后系统不崩溃 | 自动降级，无异常退出 |
| NF-04 | 可扩展性 | 支持多路侧节点接入 | MVP支持1路侧+1车端 |
| NF-05 | 可部署性 | 支持 Docker 化部署 | docker-compose 一键启动 |

## 5. 数据需求

### 5.1 训练数据
- **DAIR-V2X**：路侧+车端协同标注数据
  - 路侧图像 + 3D标注
  - 车端图像 + 3D标注
  - 时间同步标签

### 5.2 测试数据
- DAIR-V2X 测试集（离线评估）
- 华为小车沙盘实采数据（在线验证）
- 仿真数据（CARLA，兜底方案）

## 6. 验收标准 (MVP Definition of Done)

- [ ] 路侧感知可在 DAIR-V2X 上输出行人轨迹预测，ADE < 1.0m
- [ ] 路侧→车端特征传输延迟 < 100ms
- [ ] 车端可基于协同信息做出制动决策
- [ ] 通信中断时车端可平滑退化
- [ ] 云端孪生可3D渲染场景并支持回放
- [ ] 至少完成1个"鬼探头"场景端到端演示
- [ ] 核心模块单元测试覆盖
- [ ] 项目文档完整（README、架构、API、部署指南）

## 7. 技术约束

- 路侧推理设备：NVIDIA Jetson (目标) / PC GPU (开发)
- 通信协议：MQTT v3.1.1 / v5.0
- 模型框架：PyTorch ≥ 2.0 + PyG
- 前端框架：Three.js + Vite
- 后端框架：FastAPI
- 时序数据库：InfluxDB 2.x
