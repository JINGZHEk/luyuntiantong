# 路云天瞳大屏视觉预览设计

## 目标

在不改变当前大屏功能、数据流和三维场景逻辑的前提下，制作三套独立的视觉预览，供汇报展示场景比较。预览先与现有源代码隔离；用户选定方案后，再迁移到 `frontend/src/pages/zhiluwujie/`。

## 不变范围

- 保留 `ZhiluWujieScene` 的 Three.js 场景、车辆运动、轨迹、交通灯、RSU 覆盖和相机模式。
- 保留 `ZhiluWujiePage` 当前的模式切换：单车聚焦、全路网流量、V2I 基础设施、算法参数。
- 保留指标、风险状态、日志、吞吐量、连接状态和已有交互。
- 不修改 YOLO、DeepSORT、STGNN、MQTT、WebSocket、API 或数据结构。
- 不新增虚构业务功能；预览只改变显示层。

## 共同视觉原则

- 目标气质：高级、克制、具有产品展示感，同时保留交通指挥系统的可信度。
- 视觉中心：三维路口占据主要注意力，面板成为辅助说明层。
- 色彩：以 `#080909`、`#151716`、`#F2F0EA`、`#B79A68` 为基础；`#E4B44F` 只表示预警，`#D95F52` 只表示危险。
- 删除或弱化高饱和紫色、全屏扫描线、粒子装饰、角标框线和大面积霓虹光晕。
- 字体：中文使用系统无衬线字体，数据使用等宽字体；标题采用较大字号和较宽留白，不使用过度科幻字效。
- 动效：只保留车辆/轨迹运动、风险变化、模式切换和必要的状态刷新；支持 `prefers-reduced-motion`。
- 信息标签必须真实表达状态；演示回放状态可以低调展示，但不伪装成生产在线状态。

## 方案 A：极简科技展台

最接近参考网站的产品展台气质。画面四周留出较大空白，左侧只有系统标题和三项关键指标，右侧只保留当前风险卡。其他模式内容通过顶部或侧边轻量切换展开。

```text
┌──────────────────────────────────────────────────────────────┐
│ 路云天瞳                         SYSTEM ONLINE   11:25:08     │
│                                                              │
│  运行状态          三维路口 / 车辆 / 风险区域                 │
│  28 FPS             （主视觉区域）             CURRENT RISK   │
│  12 ms                                      TTC  0.5 s        │
│                                            AEB  READY         │
│                                                              │
│  [EGO] [FLOW] [V2I] [ALGO]                  EVENT TIMELINE   │
└──────────────────────────────────────────────────────────────┘
```

优点：高级感最强、汇报画面最干净。缺点：同时展示的指标较少。

## 方案 B：高级交通指挥中心（推荐）

保留当前大屏的信息密度，但将面板改为低对比度的深灰玻璃层，采用严格的三栏网格。三维场景仍是中心，右侧风险信息保持持续可见，适合既要展示又要体现日常值守能力的场景。

```text
┌──────────────┬──────────────────────────────────┬──────────────┐
│ SYSTEM       │                                  │ ACTIVE RISK  │
│ 4 KPI        │          INTERSECTION            │ EGO-01       │
│              │      vehicles / trajectories     │ TTC / risk   │
│ MODES        │                                  │ decision     │
│ EGO FLOW     │                                  │ event log    │
│ V2I ALGO     │──────────── timeline ────────────│              │
└──────────────┴──────────────────────────────────┴──────────────┘
```

优点：功能保留完整、可信度和高级感平衡最好。缺点：比方案 A 更像控制台。

## 方案 C：电影感数字孪生

以大标题、时间线和单一风险叙事为主，面板数量最少；将当前场景事件组织为“检测—预警—制动—解除”的连续故事，适合现场汇报和视频录制。

优点：演示节奏和记忆点最强。缺点：日常操作信息密度最低。

## 预览实现方式

- 新增独立预览入口和样式文件，不覆盖 `frontend/src` 下的现有页面。
- 预览复用当前页面的文案、指标、风险阶段和模式名称，避免设计稿与真实功能脱节。
- 每套方案都提供 1920×1080 视口下的可切换状态：正常、预警、紧急制动。
- 通过统一的预览选择器比较 A/B/C，不修改现有路由和运行时配置。

## 验收标准

- 现有大屏源代码在预览阶段无修改。
- 三套方案均能清楚表达当前模式、关键指标和风险状态。
- 首屏视觉焦点为三维路口，而不是装饰性面板。
- 正常状态不出现大面积紫红光污染；危险状态仍能在 1 秒内识别。
- 用户确认方案后，才开始迁移到正式页面。
