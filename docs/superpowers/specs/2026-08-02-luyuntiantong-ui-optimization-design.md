# 路云天瞳前端 UI 优化设计规格

## 1. 目标与用户

本次改造将现有 React 前端从“功能完成的 Demo”提升为可用于日常查看、故障定位和项目演示的 V2X 感知控制台。主要用户是需要快速判断路口风险、查看实时链路状态、回放事件和核对模型评估结果的运维/算法人员。

每个页面的首要任务保持明确：

- 总览：在一个视窗内判断系统是否在线、当前风险在哪里、风险是否正在变化。
- 实时监控：确认数据链路、设备订阅和感知消息是否正常。
- 事件回放：选择事件并复现某一帧的空间状态、TTC 与风险趋势。
- 模型评估：对比模型指标、达标情况和消融结果，并导出报告。
- 系统设置：完成主题、刷新、接口、阈值和配置同步管理。
- 演示模式：不依赖后台壳层，突出数字孪生场景和实时态势。

默认不改后端协议、业务计算和 Zustand 数据模型；UI 层只在必要时补充展示所需的派生数据（如 KPI sparkline 历史和趋势方向）。

## 2. 设计方向

### 2.1 视觉语言

保留现有深色 V2X 科技方向，但收敛霓虹装饰的使用范围：青色用于实时信号和交互焦点，绿色用于在线/通过，黄色与橙色用于预警，红色仅用于高危和错误。装饰必须表达“实时数据流”或“风险状态”，不作为无语义背景。

核心色板：

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| Deep Space | `#050816` | 页面底色与演示模式底色 |
| Midnight | `#0A0E1A` | 侧边栏、顶部栏和深层容器 |
| Panel | `#101830` | 卡片/面板基底 |
| Signal Cyan | `#00D4FF` | 主交互、链路、图表主线 |
| Online Green | `#00FF88` | 在线、通过、正向趋势 |
| Risk Orange | `#F97316` | 高风险过渡状态 |
| Critical Red | `#FF4D4F` | 严重风险、错误和断链 |
| Text Primary | `#E0E6F0` | 主文本 |
| Text Secondary | `#8892A4` | 辅助信息、轴标签、时间戳 |

字体角色固定为 Inter（正文）、Orbitron（KPI/标题/状态数值）、JetBrains Mono（日志/技术值）。字体加载失败时使用系统无衬线和等宽回退字体。

### 2.2 记忆点与动效

“路端感知信号轨”作为唯一品牌记忆点：面板顶部 1px 信号线、四角 L 型边线、扫描线和数据流粒子只用于总览/演示场景、实时日志和风险卡片。页面中不再随意叠加发光阴影。

动效分三层：

1. 页面层：页面根节点 `fade-in`，子卡片按顺序错开进入。
2. 数据层：KPI 数值翻转、风险升级闪烁、新日志左侧滑入、数据源标签切换。
3. 场景层：传感器锥体、风险环、交通灯和粒子持续低频呼吸。

所有持续动画都必须在 `prefers-reduced-motion: reduce` 下关闭或降级为静态状态；所有可点击元素必须有可见键盘焦点。

## 3. 页面与布局

### 3.1 应用壳层

- 侧边栏默认 220px，收起后保留品牌图标；Logo 使用雷达/盾牌 SVG，品牌文字使用 Orbitron。
- 顶部栏高度 64px，左侧为面包屑、页面标题和描述，右侧为数据源、WebSocket 状态、当前时间和主题入口。
- 内容区统一 20px 内边距，页面间距使用 8px 栅格 token；移动宽度下侧边栏收起，内容改为单列。
- 统一 Ant Design token 与平台 CSS 变量，避免 Ant 默认蓝白皮肤穿透到暗色控制台。
- 根布局使用 `data-theme="dark|light"`，保证浅色主题覆盖 body、侧边栏、头部、卡片、表单和图表，而不是只覆盖部分卡片。

### 3.2 页面头部

`PageHeader` 作为所有业务页面的第一视觉区，支持 `title`、`subtitle`、`icon`、`extra`，并提供加载/错误状态下的一致间距。Dashboard、Monitor、Replay、Evaluation、Settings 全部接入；Presentation 使用独立的全屏标题栏。

### 3.3 总览页

总览布局为“指标带 → 三栏态势区 → 日志流”：

```text
┌──────────────────────────────────────────────────────────┐
│ PageHeader: 当前路口 / 数据源 / 操作                     │
├──────────────┬──────────────────────────┬────────────────┤
│ 实时风险榜   │ 3D 路口与传感器范围       │ TTC / 风险趋势 │
│              │ 车辆/行人/盲区/数据流      │ 制动触发趋势   │
├──────────────┴──────────────────────────┴────────────────┤
│ 实时日志流 + 筛选 + 自动滚动                             │
└──────────────────────────────────────────────────────────┘
```

3D 场景是页面视觉中心；风险榜作为行动入口，图表作为变化趋势解释，日志只在底部承载诊断信息。桌面端比例约为 20% / 55% / 25%，窄屏按风险榜、场景、图表、日志顺序堆叠。

### 3.4 其他页面

- Monitor：顶部提供 Demo 状态与操作，下面用连接/Topic、感知卡片、原始消息三个层级表达链路。
- Replay：事件列表和筛选在上方，选中事件后采用“场景 60% + 指标/趋势 40%”布局；未选中使用明确的 EmptyState。
- Evaluation：数据源/报告选择与摘要置顶，指标卡、达标列表、对比图、消融详情按信息优先级排列；导出按钮固定在详情区标题右侧。
- Settings：按外观、数据刷新、云端服务、阈值、云端同步、配置管理分组；每项都显示标签、说明、控件和同步反馈。
- Presentation：保持全屏，顶部 72px、场景约 65%、右侧数据面板约 35%、底部事件时间轴；移动/窄屏下改为场景优先的纵向布局。

## 4. 组件改造边界

### 4.1 设计系统与共享组件

- `design-tokens.ts` 补齐排版、间距、圆角、阴影、动效、层级和语义 token。
- `colors.ts` 补齐渐变、语义色和浅色主题映射；ECharts 主题与 CSS 变量使用同一色源。
- `global.css` 负责 reset、CSS 变量、Ant 覆盖、工具类、卡片/边框/动画和 reduced-motion；主要组件样式使用 CSS Modules，避免新的 inline style。
- `PageHeader`、`EmptyState`、`Skeleton`、`Toast` 统一视觉与状态文案。

### 4.2 核心数据组件

- `KpiBar`：四张卡片包含图标/标签、Orbitron 数值和单位、20 点 sparkline、趋势方向/百分比；使用语义色和错开入场。
- `RiskList`：继续使用自定义列表而不是 Ant Table；每行有风险色竖线、排名、目标/位置/TTC、风险分和等级；critical 行有低强度脉冲，排序按钮提供键盘焦点。
- `LogStream`：终端排版、时间戳、圆点级别、`[source]`、错误行边线、扫描线、过滤器和自动滚动状态；不再使用 `any` 作为 CSS 变量类型逃逸。
- 图表：统一注册 `v2x-dark`，自定义 tooltip、网格、坐标轴和面积渐变；Gauge 使用无指针的进度弧，Line/Bar/Radar 按主题提供发光和渐变。

### 4.3 3D 场景

保留现有 `Road`、`Vehicle`、`Pedestrian`、`Obstacle`、`TrafficLight`、`BuildingWireframe`、`OcclusionZone`、`DataFlowParticles` 组件边界，集中完成材质、灯光、Bloom 和镜头模式：

- 路面、车道线、停止线、人行横道和青色道路边线形成可辨识路口。
- 自车具备车灯、传感器锥体、传感器环和风险光环；轮子在有速度时旋转。
- 四角交通灯、线框建筑和随机窗灯补足空间层次；遮挡盲区用红色透明体与边框表达“鬼探头”卖点。
- 粒子数量控制在 150–200；Bloom 只作用于高亮材质；`orbit/follow/cinematic` 三种镜头保持可切换。

## 5. 数据、状态与错误反馈

- 继续复用现有 stores/services；数据源标签必须与 store 的 live/mock 状态一致。
- 断开连接显示固定位置的状态带或错误状态；重连、Demo 操作、云端同步、导入导出均提供成功/失败 Toast。
- 空数据使用 EmptyState，加载使用 Skeleton/PageLoading，错误使用带重试动作的 Result，不再只显示“暂无数据”。
- 所有按钮文案使用动作结果一致的主动语句，例如“保存配置”对应“配置已保存”。
- 真实评估数据不可用时保留 mock，但明确显示“演示数据”，避免与 live 数据混淆。

## 6. 性能与质量边界

- 继续使用已安装的 `@react-three/postprocessing`、压缩插件和可视化插件，不重复增加依赖。
- 关键组件改为细粒度 Zustand 选择器，避免整个 store 更新触发不相关页面重渲染。
- 趋势数据保持最多 60 点；日志和风险列表先保持现有数据规模，只有在实际数据规模超过视窗时再引入虚拟列表。
- 保持路由懒加载；ECharts 使用 `lazyUpdate`/稳定 option，3D 不引入不必要的纹理。
- 验证命令：`npm run build`、`npm run lint`、`npm run test:unit`；手动检查五个业务路由、`/presentation`、暗/亮主题、窄屏和 reduced-motion。

## 7. 交付验收

验收以任务书的“设计系统、布局、组件、3D 场景、页面、性能、代码质量”七组标准为准。除视觉截图外，以下证据必须可复核：

- 每个页面都存在统一头部或明确的全屏标题栏。
- 核心组件的状态、筛选、排序、导出、重连和主题切换可操作。
- TypeScript、lint、单元测试和生产构建通过。
- 代码扫描不再新增硬编码风险色、无意义 inline style 或 `any` 逃逸；保留的动态尺寸样式必须能说明原因。
- 关键页面在桌面和窄屏均不出现横向溢出；键盘焦点和 reduced-motion 规则可见生效。
